# 合并为单流程：32 题 → 初步画像 → AI 深聊 → 深度报告

## 背景

原来的双轨（体验版 / AI 深聊版）让用户在首页先做一次产品选择，而且 AI 版要求用户自备 API Key。用户决定合并成一条流程，由站点提供模型 Key，降低门槛。

## 决定

- **单一流程**：32 题 → 初步画像 → AI 深聊（4–8 问）→ 深度报告。
- **初步画像**由规则引擎生成，作为即时产出和失败兜底；最终报告把规则判断与深聊洞察合并（每个象限卡显示「规则基线」）。
- **模型由站点统一配置**：前端只调用 `AI_PROXY_URL`（腾讯云云函数），Key 只存在云函数环境变量里；前端不接收、不保存 Key。
- **代理只认固定配置**：`BASE_URL + MODEL` 来自环境变量，前端不能传任意地址，避免开放中继；代理做 CORS、轮次上限、`max_tokens` 上限和尽力限流。
- **对话不落盘**：不写浏览器存储，刷新即清空；旧 `h30.ai.v1` 状态直接忽略。
- **提示词改为追问式**：基于已完成的 32 题做 4–8 个追问，不重复已答内容，输出中文 JSON（新增 `comparable` 字段）。

## 代价

- 站点维护者承担模型费用，需要在服务商后台设置额度上限。
- 32 题答案会发送给模型服务商，放弃「回答不离开设备」的旧承诺；全站文案已同步改写。
- 严格「每 IP 每天 1 次」需要数据库/Redis；当前为内存尽力限流 + 服务商额度上限。

## 取代

- 取代 ADR-0001（双轨产品）。
- 取代 ADR-0002（用户自带 Key、浏览器直连）。
- 取代 ADR-0003（访谈状态只存本人浏览器）。
