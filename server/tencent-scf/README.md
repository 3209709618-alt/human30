# 腾讯云云函数代理（AI 深聊）

这个函数只有一个职责：**替网页保管 Key，并把请求转发给模型服务商**。前端只调用它的 HTTPS 地址，永远拿不到 Key。

## 1. 新建函数

1. 打开腾讯云控制台 → **云函数 SCF** → 新建函数。
2. 运行环境选 **Node.js 18**，函数类型选「事件函数」。
3. 把本目录的 `index.js` 和 `package.json` 上传（或在线编辑粘贴 `index.js`）。
4. 执行超时改成 **60 秒**，内存 128MB 即可。

## 2. 配置环境变量

在函数的「函数配置 → 环境变量」里填：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `API_KEY` | 是 | 你的模型服务商 Key。**只填在这里，不要写进代码或仓库** |
| `BASE_URL` | 否 | 默认 `https://api.siliconflow.cn/v1` |
| `MODEL` | 否 | 默认 `zai-org/GLM-5.3-Flash` |
| `ALLOW_ORIGIN` | 否 | 建议填 `https://3209709618-alt.github.io` |
| `ACCESS_CODES` | 否 | **兑换码白名单**，逗号/空格/中文逗号分隔。留空 = 不校验（任何人可调用）。设置后前端必须带 `X-Access-Code` 请求头（或 `body.code`）才能调用，无效请求在转发模型前就被拒绝，不消耗额度 |
| `MAX_TOKENS` | 否 | 单次最大输出，默认 4096 |
| `RATE_LIMIT` | 否 | 每个 IP 每小时请求上限，默认 30 |

> **兑换码说明**：白名单模式，一个码可被重复使用；要做到「一码一人」需要额外的计次存储（当前未实现）。
> 增删码只改这个环境变量即可，改完即时生效，不用重新部署代码。

以后想换服务商或模型，**只改这里的环境变量**，不用改前端代码：
- 换模型：改 `MODEL`；
- 换服务商：改 `BASE_URL` + `API_KEY`（OpenAI 兼容接口即可）。

## 3. 开启 HTTPS 访问

在函数详情里开启 **「函数 URL」**（HTTP 访问），得到一个 `https://xxx.tencentscf.com` 之类的地址。默认域名一般不需要备案。

把这个地址填进 `assets/config.js`：

```js
window.HUMAN30_CONFIG = {
  AI_PROXY_URL: 'https://你的函数地址',
  // ...
};
```

## 4. 自测

```bash
# 健康检查（GET）
curl https://你的函数地址

# 发一条消息（POST）
curl -X POST https://你的函数地址 \
  -H "Content-Type: application/json" \
  -d '{"messages":[{"role":"user","content":"你好，请回复收到"}]}'
```

返回 `{"content":"..."}` 就说明通了。

## 5. 限流与预算

- 函数内置**尽力而为**的内存限流（按 IP、每小时）。云函数冷启动会重置计数，所以它不是严格限流。
- 真正的预算闸门是**模型服务商后台的额度上限**：去硅基流动控制台把每月额度设成你能接受的上限。
- 前端另外限制：每次深聊最多 8 轮追问、单次输出最多 4096 token。
- 如果要做严格的「每个 IP 每天 1 次」，需要接一个数据库/Redis 存计数（云开发 CloudBase 云数据库即可）；当前版本为了零额外依赖，没有做。

## 6. 安全

- 不要把 `API_KEY` 写进 `index.js`、`config.js`、任何提交到 GitHub 的文件。
- 不要在前端传任意 `baseUrl`——本函数只认环境变量里的 `BASE_URL`，避免变成任人调用的开放中继。
- `ALLOW_ORIGIN` 建议写成你的站点域名，而不是 `*`。
